# MQTT

* Added MQTT integration. The portal publishes change events to an MQTT broker so external systems (e.g. BELY) can react to CDB changes.
  * Shared `cdb-base-mqtt` library for MQTT connection and event serialization, used by both BELY and CDB.
  * Events include the affected entity, the user who triggered the change, and details of what changed.
  * Consistent operation names across events (add, update, delete, trash, restore).
* Entity events
  * Item add, update, and delete.
* Property events
  * Property value add, update, and delete, with the before and after values.
* Log events
  * Log entry add, update, and delete, with the before and after text.
  * Log attachment add.
* Machine design events
  * New machine design, including ones created from a template.
  * Assigned item update.
  * Move within the machine hierarchy.
  * Represented element update, including changes made through a template.
  * Trash and restore.
* Inventory events
  * Location update.
  * Assembly element assignment and clearing.
* Configuration
  * `make mqtt-configuration` and `make configure-mqtt` (with `-dev` variants) to create and deploy the MQTT connection configuration.

# API

* Ability to update an existing log entry.
* Ability to delete a log entry.
* Attachments added via the API, utilities, and the portal now use the same workflow.

# Testing

* Added unit tests for all MQTT event models and change detection.
* Added an MQTT test framework that listens to the broker and verifies published events.
  * Python API tests for events that can be triggered via the API.
  * Selenium tests for events only available in the portal.
  * MQTT tests are included in `make test`.
* CI runs the shared MQTT library tests when it changes.
* Documented the new tests in the python client and Selenium READMEs.

# Bug Fixes

* Destroy is now called after a successful `updateOnRemoval`, removing the need for workarounds in the log list views.
