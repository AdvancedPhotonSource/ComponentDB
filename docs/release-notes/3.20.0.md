# Platform

* Upgraded the application server to Payara 7 (Jakarta EE 11) and Java to the Java 25 LTS (Eclipse Temurin).
  * Same Payara and Java versions on Linux x86_64 and macOS (Intel and Apple Silicon); all support versions are set in `support/bin/versions.sh` and can be overridden from the environment.
  * Existing installations must rebuild the support software (`make support`); see `docs/update/README.md`.
  * `make support` now creates the Payara `production` domain itself and moves the Payara data grid (Hazelcast) off port 5900, which conflicts with VNC / macOS Screen Sharing.
  * NetBeans 32 and Ant 1.10.18 for development; `make support-netbeans` runs NetBeans on the bundled JDK.
* Migrated the portal, REST API, plugins, and unit tests from `javax.*` to the `jakarta.*` namespace.
* Upgraded PrimeFaces to 16, OmniFaces to 5, and Apache POI to 5.
  * Dialogs keep their own background and scroll when their content is taller than the window.
  * List filters that offer a fixed set of choices (e.g. owner group, category, topic) use the standard drop-down.
  * Upload limits (file count, size, type) are checked in the browser before uploading, with standard PrimeFaces messages.
  * Login fields show their hints as placeholders.
  * The user settings table on the user edit page follows the user's items-per-page setting and keeps its filters.
  * Name, alternate name, and QR id fields check their value while typing with a lighter request that no longer reloads the field.
* MQTT connector updated to `mqtt-rar` 1.0.0; re-run `make configure-mqtt` after upgrading.
* Warnings from the REST API documentation (Swagger) and the MariaDB driver now appear in the server log.

# MQTT

* Added MQTT integration. The portal publishes change events to an MQTT broker so external systems (e.g. BELY) can react to CDB changes.
  * Shared `cdb-base-mqtt` library for MQTT connection and event serialization, used by both BELY and CDB.
  * Events include the affected entity, the user who triggered the change, and details of what changed.
  * Consistent operation names across events (add, update, delete, trash, restore).
* Entity events
  * Item add, update, and delete.
* Property events
  * Property value add, update, and delete, with the before and after values.
* Log events
  * Log entry add, update, and delete, with the before and after text.
  * Log attachment add.
* Machine design events
  * New machine design, including ones created from a template.
  * Assigned item update.
  * Move within the machine hierarchy.
  * Represented element update, including changes made through a template.
  * Trash and restore.
* Inventory events
  * Location update.
  * Assembly element assignment and clearing.
* CDB MQTT message broker (`cdb-mqtt`)
  * Pluggable Python framework for reacting to CDB events: drop handler classes into a directory and implement methods such as `handle_item_log_add` or `handle_machine_design_move`.
  * Typed models for every CDB event, global and per-handler YAML configuration, and optional CDB API access.
  * Example handlers and a systemd service template included.
* Shared MQTT message broker base (`cdb-bely-message-broker-base`)
  * Generic Python framework extracted from the BELY MQTT framework; `cdb-mqtt` is built on it and BELY will migrate to it.
  * Applications register their topics and event models; handlers receive typed events through matching `handle_<event>` methods.
  * Handler discovery from a directory, MQTT topic wildcard matching, and global and per-handler YAML configuration.
  * Reusable CLI (`start`, `list-handlers`) with application-specific defaults and environment variables.
* Configuration
  * `make mqtt-configuration` and `make configure-mqtt` (with `-dev` variants) to create and deploy the MQTT connection configuration.

# Testing

* Unit test project builds against Jakarta EE 11 and Java 25.
* Added unit tests for all MQTT event models and change detection.
* Added an MQTT test framework that listens to the broker and verifies published events.
  * Python API tests for events that can be triggered via the API.
  * Selenium tests for events only available in the portal.
  * MQTT tests are included in `make test`.
* CI runs the shared MQTT library tests when it changes.
* Added tests for the Python message broker base and the CDB MQTT message broker, with sample payloads for every CDB event; both run in CI.
* Documented the new tests in the python client and Selenium READMEs.
* Selenium tests updated for PrimeFaces 16 and made more reliable.
  * Failed tests save a log, screenshot, and page source to `test-failures/`; timeouts report the page, visible messages, and browser console errors.
  * Reruns of a failed test are labelled by attempt, so their logs and screenshots are kept separately.
  * Tests wait for pending PrimeFaces requests and the loading dialog before clicking.
  * Import tests check that the import succeeded instead of only finishing the wizard.
  * Payara needs at least a 4 GB heap for the parallel suite (see README).
